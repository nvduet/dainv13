# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Group-expense ledger web app ("Sổ chi nhóm bạn") on Cloudflare Workers + D1. UI text, API error messages, README and SPEC are in Vietnamese; keep new user-facing strings in Vietnamese. `SPEC.md` is the source of truth for business rules (permissions, money rules, limits, acceptance criteria) — read it before changing behavior.

A multi-phase upgrade (2026-11: backend refactor, password model, frontend refactor, redesign, Detail features, themes) is complete; `REFACTOR_PLAN.md` records what was done, the owner decisions still open (§6) and where the local test harness lives — read it before changing behavior.

`wrangler.toml` enables Workers Logs (`[observability]`) and turns off per-version preview URLs (`preview_urls = false`); the deploy script's health check uses the main `workers.dev` address.

No package.json, no build step, no bundler, no linter, no npm dependencies. Plain ES modules everywhere. There is intentionally **no local dev server or local database workflow** in the repo; migrations are applied only to remote D1 during deploy. Never deploy or run wrangler/secret scripts unless the owner asks.

Must stay inside the Cloudflare **free plan**: Workers 10 ms CPU and 50 subrequests per request (each D1 query counts, one `db.batch()` counts once); D1 5M rows read / 100k rows written per day (indexes add written rows), 100 bound params, 100 KB SQL, 2 MB per value. Judge every change by D1 queries, rows read and rows written per request.

## Architecture

### Worker (`worker/`)
- `index.js` — entry `fetch`: resolves `/api/g/<slug>/…` to a ledger (one query, also reads `schema_version`), runs the lazy per-ledger schema upgrade, serves `/g/<slug>` as `index.html` with security headers, maps errors (`ApiError` → its status, anything else → generic 500).
- `router.js` — one `ROUTES` table; each entry is `{ method, pattern, scope, admin, rateLimits, trackDetail, handler }`. The pipeline order is fixed: route match (unknown → 404 with no D1 access) → Origin check for non-GET → admin session computed once → admin gate (route's message) → rate limiters in order → Detail before-snapshot (trackDetail) → handler → after-snapshot + audit-session recording (failures are logged, never turn a committed write into a 500). Add new endpoints here, never with ad-hoc path checks.
- `routes/*.js` — handlers (state, session, ledgers, settings, members, member-groups, expenses, payments, history, audit). Path params are decoded lazily with a safe decoder (malformed escape → the route's 404 text).
- `http.js` (ApiError/`error()` with optional response headers, json, readJson with a 100 KB cap and `{ allowEmpty }`, page/API security headers), `auth.js` (HMAC session cookie, cached CryptoKey, constant-time `secureEqual`), `rate-limit.js`, `operations-password.js`, `ledger-schema.js`, `audit.js`, `validation.js`.
- **Operations password** (secret `HISTORY_RESTORE_PASSWORD`, must differ from `ADMIN_PASSWORD`, else 503) guards create ledger, delete ledger, Store and restore. Create and Store ask once per Admin session: the authorization row lives in the **unprefixed** `admin_session_store_auth` (always via `ctx.globalDB`, 8-hour expiry) and covers every ledger; the per-ledger copies of that table are unused. Delete and restore always ask. Per-ledger delete-password hashes (`ledgers.delete_password_*`) are legacy and ignored; there is no PBKDF2 any more.
- **Rate limits** (`RATE_LIMITS`): every bucket lives in the unprefixed `rate_limits`; ledger-scoped buckets (write 300 guest / 500 Admin per 15 min, member, member-group) include the ledger slug; login, create-ledger and the shared `restore-password` bucket (all four operations-password checks; a missing password spends nothing) are global per client, IPv6 grouped by /64. Every 429 carries `Retry-After`. `rateLimitStatements()` + `refuseIfLimited()` let a limiter ride in the caller's own batch (ledger creation stays at 4 D1 queries).

### Multi-ledger via table-name prefixing
- The default ledger (`id = 'default'`, slug `chill-guys`, served at `/` and `/api/...`) uses the unprefixed tables. It cannot be deleted. Other ledgers use `ledger_<32-hex-id>_<table>` tables, created atomically (ledgers row + copied CREATE statements in one batch) from the default tables' current `sqlite_master` SQL.
- `ledgerDatabase()` returns a fail-closed `{ prepare, batch }` object whose `prepare()` rewrites table identifiers (`rewriteLedgerSql`, case-insensitive, memoized). `rewriteLedgerSql` does NOT prefix names in `DROP TRIGGER`/`DROP INDEX` — DDL for ledger copies must use explicit quoted `ledger_<id>_…` names on the raw database.
- Truly global tables: `ledgers`, `global_app_settings`. The unprefixed `rate_limits` holds every limiter bucket, the unprefixed `admin_session_store_auth` holds the operations-password authorization for all ledgers, and the unprefixed `audit_log` also receives settings audits.
- **Schema evolution:** migrations only touch the unprefixed tables. Existing ledger copies are upgraded lazily: the slug lookup reads `ledgers.schema_version`; below `LEDGER_SCHEMA_VERSION`, `upgradeLedgerSchema()` runs idempotent DDL on the raw DB (try/catch, retried later). For any new per-ledger schema change: add a migration for the default tables, bump `LEDGER_SCHEMA_VERSION`, add the DDL to `upgradeLedgerSchema`, and insert new ledgers with the new version. Never edit applied migrations (0001–0013).
- A new per-ledger table must be added to `LEDGER_TABLES` (ordered parents first; drop order is the reverse).

### Detail audit trail
`trackDetail` routes record "sessions" in `audit_sessions` (30-minute idle window, max 999, `audit_session_anchor` holds the baseline) from before/after snapshots of members/groups/expenses (one batch each). `audit_log` (per-field rows, capped at 999 by an O(1) trigger) is write-only forensics. Actor values: `AUDIT_ACTOR` (`admin` / `public`, enforced by a CHECK constraint); `guest` only exists as an `audit_sessions` flag.

### API notes
- `PUT /api/expenses/:id` accepts any of `payerId`, `date`, `description`, `amountVnd` and `participantChanges: { add, remove }` (merged on the server so ticks from several phones don't overwrite each other). A body with the legacy full-list `participantIds` (only tabs opened before that change send it) gets 409 "Trang đang dùng phiên bản cũ. Hãy tải lại trang rồi thử lại.". Participant writes are diff-based; a no-op save writes nothing.
- `POST /api/admin/ledgers` takes `{ name, password }` (password only needed when the session is not yet authorized) and returns `storePasswordVerified: true`; `DELETE /api/admin/ledgers/:slug` takes `{ password }` (an empty body reads as a missing password).
- `PUT /api/admin/payments/total` is atomic (delta computed in SQL) and returns an `adjustment` object the client applies locally.

### Money rules (from SPEC)
- Amounts are stored as integer VND (may be negative). UI input is in thousands of VND, `,` or `.` decimal, rounded half-up to whole đồng (`parseThousandInput`).
- Equal split in whole đồng; the remainder goes one đồng at a time in member list order so shares always sum to the expense amount.
- `balance = share - paidExpense - paidToAdmin + refunded`. Positive = member owes Admin; members are never matched against each other.
- "Paid to Admin" totals are edited by inserting delta rows into `payment_adjustments`; original `payments` rows are never rewritten.
